# Review deploy & skrip operasional — 2026-11-25

## Lingkup

Berkas deploy baru di repo ini dan di `portfolio-frontend` (branch
`feat/deploy-docker`): `deploy/Dockerfile`, `deploy/docker-compose.yml`,
`deploy/env.example`, `deploy/lib.sh`, `install.sh`, `update.sh`, `status.sh`,
`backup.sh`. Ditinjau dua kali secara terpisah: kebenaran (code-reviewer) dan
keamanan (security-auditor). `deploy/lib-dasar.sh` tidak ditinjau isinya — ia
salinan apa adanya dari skill project-standard.

## Yang diuji

Dijalankan di VM Linux lokal (Ubuntu 24.04, Docker 29, 2 vCPU / 4 GB), dua
putaran (sebelum dan sesudah perbaikan review):

| Skenario | Hasil |
|---|---|
| Pasang pertama, pasang ulang, ubah konfigurasi runtime | lulus |
| Update dengan tarik kode; update saat skrip update sendiri berubah | lulus |
| Versi yang crash saat start → kembali otomatis ke versi lama | lulus |
| Migrasi rusak → update batal sebelum versi diganti | lulus |
| `--rollback`; `--ref=<commit>` lalu kembali ke cabang yang diikuti | lulus |
| Cadangan; pemulihan database (tukar) dan unggahan; arsip rusak ditolak | lulus |
| Database di luar stack (`COMPOSE_PROFILES` tanpa `db`) | lulus |
| `status.sh`: database mati, backend mati, kontainer berhenti, versi tidak cocok | lulus |
| Stop/start lewat systemd | lulus |
| Frontend: prerender dengan data saat build, regenerasi ISR di akar hanya-baca | lulus |

**Tidak diuji:** jalur pemasangan Docker otomatis (`apt`), mode tanya-jawab
interaktif pada Docker sungguhan (hanya logikanya, oleh peninjau), server
produksi yang sebenarnya, reboot sungguhan, cron yang benar-benar berjalan
pukul 02:30, alarm webhook/Telegram, `govulncheck` (tidak terpasang lokal; CI
menjalankannya).

## Risiko diterima / ditunda

- **Pemilik folder repo setara root.** Cron dan systemd menjalankan skrip dari
  folder repo sebagai root, dan `rapikan_pemilik_repo` di `lib-dasar.sh`
  menjalankan `git` sebagai root atas `.git` milik pemilik folder (konfigurasi
  git di sana bisa mengeksekusi perintah). Mitigasi sekarang: peringatan di
  `install.sh` dan anjuran clone sebagai root di `/opt`. Perbaikan menyeluruh
  (menyalin skrip ke lokasi milik root) ditunda; perbaikan `lib-dasar.sh` harus
  dilakukan di sumbernya (skill), bukan di salinan ini.
- **API memakai pengguna PostgreSQL bawaan image** (superuser database itu).
  Role aplikasi terpisah ditunda.
- **Image dasar dipatok dengan tag, bukan digest.**
- **Cadangan di disk yang sama dengan data.** Tempat salinan luar belum diputuskan.
- **Port yang diikat ke alamat jembatan Docker** terjangkau semua kontainer lain
  di server yang sama.

## Sebelum produksi

- Reverse proxy ber-TLS di depan kedua layanan; tanpa itu jangan membuka port
  API ke internet dan jangan login admin.
- Isi SMTP bila password admin perlu bisa diganti.
- Jalankan `sudo ./install.sh` sekali di server sungguhan dan ikuti dengan
  `sudo ./status.sh`; uji pulihkan satu cadangan di sana.
- Putuskan tempat salinan cadangan di luar server.
